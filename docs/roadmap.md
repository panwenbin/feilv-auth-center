# 路线图

## 总原则

路线图服务于一个核心目标：

> 尽快让 `feilv-auth-center` 真实支撑 `fei.lv` 工具矩阵，而不是长期停留在规划层。

阶段设计优先围绕：

- 真实接入
- 商业化闭环
- 可持续演进

---

## Phase 0：项目立项与边界确定

### 目标

明确项目定位、MVP 边界、技术栈和演进方向，避免项目从一开始就发散。

### 交付物

- README
- positioning
- MVP
- architecture
- roadmap
- todo

### 验收标准

- 能清楚回答为什么做这个项目
- 能清楚回答 v0.1 做什么、不做什么
- 技术栈和部署方向明确

---

## Phase 1：基础账号与应用模型

### 目标

搭建最基础的身份中心骨架。

### 范围

- 用户注册 / 登录 / 登出
- 密码哈希与安全基础
- 用户表与 Session 表
- 应用表与应用域名配置
- 基础管理接口

### 验收标准

- 可以创建用户
- 可以登录并维持会话
- 可以注册一个接入应用
- 应用可以配置来源域名或回调地址

### 风险提醒

- 容易在登录方式上发散
- 容易过早加入短信登录、第三方登录等额外能力

### 控制策略

- 第一阶段只做邮箱 + 密码
- 所有额外登录方式延后

---

## Phase 2：套餐、Feature 与 API Key

### 目标

让工具具备最基础的“登录后高级功能控制”能力。

### 范围

- 套餐模型（Free / Pro / Team）
- Feature 定义与套餐绑定
- 用户订阅关系
- API Key 生成与管理
- 工具侧能力检查接口

### 验收标准

- 用户可拥有套餐
- 不同套餐对应不同功能点
- 用户可生成 API Key
- 工具侧能根据用户权限判断是否开放功能

### 商业价值

这是从“只有流量”到“可以变现”的第一步。

---

## Phase 3：License 与第一批工具接入

### 目标

完成第一个真实业务闭环。

### 范围

- License 生成与状态管理
- 到期时间
- 绑定产品 / 套餐
- 为私有部署 / API 产品预留绑定字段
- 接入第一批 `fei.lv` 工具

### 推荐优先接入对象

- 有高级功能潜力的开发者工具
- 站长 / 运维类工具
- 后续可能提供 API 的工具

### 验收标准

- 至少一个工具已接入统一登录
- 至少一个功能通过套餐控制开放
- 至少一个授权能力可在真实产品中使用

---

## Phase 4：SSO 强化与控制台完善

### 目标

提升多工具联动体验，降低重复登录成本。

### 范围

- SSO 流程优化
- 应用接入流程优化
- 控制台页面完善
- 安全设置页面
- 基础审计日志

### 验收标准

- 用户在多个工具之间切换时登录体验顺畅
- 控制台能清晰管理账号、订阅、API Key、License

---

## Phase 5：支付与商业化增强

### 目标

把授权和订阅体系真正接入收入链路。

### 范围

- 支付对接
- 订阅开通 / 升级 / 到期处理
- 订单模型
- 企业版字段预留

### 验收标准

- 用户可以完成至少一种付费升级流程
- 订阅状态能自动影响工具权限

### 风险提醒

- 支付细节较多，容易拖慢整体节奏

### 控制策略

- 先接一种支付方式
- 先支持最简单的升级路径

---

## Phase 6：私有部署与企业授权增强

### 目标

为更高客单价场景做准备。

### 范围

- 私有部署 License
- 域名 / 实例绑定
- 激活次数限制
- 企业客户基础管理

### 验收标准

- 至少支持一种私有部署授权模式
- 企业版授权控制逻辑清晰可用

---

## 长期方向

当真实业务已经验证后，可以再考虑：

- 更标准化的 OAuth2 / OIDC 能力
- 面向更多产品的开放接入
- SDK 与接入文档
- 更完整的审计与安全能力

这些都应建立在真实接入与真实收入之上。

---

## 建议的实际执行节奏

### 第 1 周

- 完成文档
- 确定目录结构
- 初始化 backend / frontend
- 设计核心表

### 第 2-3 周

- 完成注册 / 登录 / Session
- 完成 applications 模型
- 打通最基础控制台

### 第 4-5 周

- 完成 plans / features / subscriptions / API Key
- 准备第一批工具接入

### 第 6-8 周

- 接入首个真实工具
- 完成 License 基础能力
- 验证第一条变现路径

---

## 当前最重要的事情

当前阶段最重要的不是做复杂架构，而是尽快实现：

1. 统一登录
2. 套餐控制
3. API Key / License 基础
4. 一个真实工具接入

只要这四件事形成闭环，项目就已经进入正循环。
