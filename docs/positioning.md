# 项目定位

## 核心定位

`feilv-auth-center` 是 `fei.lv` 工具矩阵的统一身份、授权、订阅与集成中心。

它首先是一个**为真实业务服务的底座**，其次才可能成长为一个对外能力平台。

## 解决的问题

随着 `fei.lv` 上的免费工具、收费工具、API 工具和私有部署工具逐步增加，会持续出现以下问题：

1. 账号体系重复建设
2. 各工具权限规则不一致
3. 订阅套餐无法统一管理
4. API Key、License、实例授权难以统一
5. 工具之间缺乏单点登录能力
6. 后续收费与企业版能力难以扩展

`feilv-auth-center` 就是用来把这些问题收敛到一个统一中心。

## 目标用户

### 第一层：内部用户

- `fei.lv` 体系下的各工具与子产品
- 管理后台
- 后续的 API 服务和私有部署实例

### 第二层：最终用户

- 使用 `fei.lv` 免费工具的普通用户
- 购买高级功能的 Pro 用户
- 使用多个工具的重度用户
- 未来可能的团队 / 企业客户

## 核心价值

### 对用户

- 一个账号通行多个工具
- 更清晰的权限与套餐体验
- 可统一管理 API Key、授权、订阅与历史记录

### 对产品

- 不再重复做登录、权限、授权、套餐逻辑
- 更容易推出收费功能
- 能更快验证新工具和新产品

### 对业务

- 让流量资产沉淀成用户资产
- 让用户资产进一步转化为订阅与授权收入
- 让未来的企业版和私有化更容易实现

## 产品边界

### 应该做的

- 用户身份管理
- 认证与会话
- 子应用接入
- 授权与套餐模型
- API Key / License / 激活机制基础
- 后续 SSO 能力基础

### 不应该过早做的

- 大而全 IAM 平台
- 面向所有开发者的通用身份云
- 超复杂组织 / 部门 / 审批流
- 脱离 `fei.lv` 场景的过度抽象

## 项目成功标准

如果在早期阶段满足以下条件，就说明方向是对的：

1. `fei.lv` 第一批工具已经接入统一登录
2. 至少有一类高级功能通过套餐 / 授权控制实现收费
3. 用户能统一管理 API Key 或 License
4. 新工具接入账号体系的开发成本明显降低

## 长期演进方向

### 近阶段

- 成为 `fei.lv` 的账户和商业化中心

### 中阶段

- 成为多工具共享的 SSO / 授权中心

### 远阶段

- 在真实业务打磨成熟后，选择性开放为独立产品或私有部署能力

## 设计原则

1. 先解决真实问题，再做抽象
2. 先保证接入简单，再追求完美架构
3. 所有新能力都必须说明“服务哪个真实场景”
4. 没有明确接入方的能力，不优先开发
